# Day 3 复盘：模型选择动作

## 调用链

`run_agent` 把当前状态交给 `qwen_choose`；百炼返回 JSON 文本；`parse_action` 检查动作类型、工具白名单与参数；循环执行工具并记录观察；最终展示文本从工具结果确定性生成。练习任务只有英文字符串，不涉及病例或医疗建议。

## 验收记录（2026-10-09）

- 用户在本机终端跑通了三步调用；助手在可联网执行环境复核，结果为 `HELLO AGENT WORLD（3 个单词）`。
- 五个固定任务的首次真实模型运行中，动作流程均完成；严格比较最终字符串为 4/5。`agent loop` 的原始模型内容是 `AGENT LOOP（2个单词）`，少了一个空格。
- 修复：`render_string_result` 只读取已执行的工具结果，统一生成最终展示文本；模型原始 `FINALIZE` 动作仍留在轨迹中。对出现偏差的 `agent loop` 进行真实调用复测，结果为 `AGENT LOOP（2 个单词）`，动作顺序为 `CALL_TOOL → CALL_TOOL → FINALIZE`。
- 本地失败路径：未知工具、无效参数、最大步骤数、实际休眠工具触发的截止时间，均可读地停止。模型连接失败也会写入轨迹。

## 经验与边界

JSON 模式和本地动作校验解决的是“能否安全解释并执行下一步”，不能保证最终文案完全一致。最终展示由受控代码根据工具结果生成更稳定。Day 3 的工具截止时间使用 `SIGALRM`，只用于 macOS/Linux 命令行主线程练习；后续 FastAPI/LangGraph 实现需采用适合异步服务的超时机制。这里的字符串工具和模型提示词都不是医疗能力验证。
