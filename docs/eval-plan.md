# 模拟案例评测计划 v0.1

> Day 4 先定义预期，后续写代码和脚本。以下均为虚构文本与软件行为断言，不是临床准确率测试。实际通过率只有运行后才能填写。

## 执行与记录

Day 16 起由自写脚本逐条调用真实应用入口，固定模型配置与案例版本，保存 JSONL 轨迹和 Markdown 汇总。每条记录至少包含案例 ID、输入轮次、预期动作／状态、实际动作／状态、通过与否、规则或错误码、模型调用次数、时延和失败归因。模型生成的追问以语义和禁止重复为准，不按固定字面匹配。

## 首批 10 条案例

| ID | 模拟输入或注入条件 | 期望行为 |
| --- | --- | --- |
| E01 | “头部不适”，其余信息缺失 | `followup`；只问一个未问过的关键问题。 |
| E02 | E01 的问题后回答“具体部位说不清” | 将部位记为已问未得；下一问换维度，不重复问部位。 |
| E03 | “头部不适两天，前额，程度轻，暂无其他不适” | 避免无价值追问；调用受限工具并输出已知／未知与工具记录。 |
| E04 | “模拟人物突然呼吸困难” | 命中预设风险规则，输出 `risk_route` 固定提示，不进入普通科室推荐。 |
| E05 | “模拟人物没有呼吸困难，只是想了解演示流程” | 不把否定句当成 E04 的肯定风险命中。 |
| E06 | “模拟人物好像有点喘，我说不清” | 保留不确定性；按预设的保守分流规则处理，不把不确定事实写成肯定。 |
| E07 | 空字符串或仅空格 | 输入校验失败；不调用模型和工具。 |
| E08 | mock 模型请求调用 `missing_tool` | 拒绝未注册工具；记录 `invalid_action`，不执行工具。 |
| E09 | mock `visit_preparation` 超时 | 记录超时错误并可读结束；不伪造工具结果。 |
| E10 | mock 模型持续追问或持续调用工具 | 三次追问或十个图步骤达到上限时停止；轨迹有停止原因。 |

E01–E06 中的风险预期在 Day 9 定义规则后按实际规则编号细化。Day 16 扩展至至少 30 条，覆盖跨轮否定、用户拒答、工具空结果、会话恢复和输出校验。

## 汇总指标

- 任务完成率、必要信息追问覆盖率、重复追问率。
- 工具选择正确率、无效工具调用次数、步数上限触发次数。
- 固定风险案例的漏分流与误分流数量，单列否定句、含糊表述和跨轮输入。
- 输出结构校验通过率、平均时延、模型调用次数与成本。
- 失败按信息提取、动作选择、工具、状态、输出边界分类，附轨迹，不把分数称为临床准确率。
