# 智能问诊与症状分析 Agent｜产品规格 v0.1

> Day 4 设计基线。仅使用虚构模拟病例做求职演示；本作品不面向真实患者，不提供诊断、治疗或用药指导。

## 1. 定位与目标用户

- **展示对象**：求职面试官、作品评审者。重点展示状态驱动决策、受限工具调用、可恢复会话和可复核轨迹。
- **操作角色**：本地演示者，输入虚构人物的症状描述和后续回答。
- **要解决的任务**：当模拟描述缺少关键信息时，Agent 依据当前状态选择一个有价值且未问过的问题；信息足够或追问到上限后，调用受限工具，给出结构化摘要。预设风险场景先由独立规则分流。
- **为什么需要 Agent**：下一步动作取决于跨轮回答、已问问题、缺失字段和工具结果，不能用一张固定问卷覆盖；每一步决策都要能从轨迹解释。

## 2. 输入、状态与输出

**输入**：一次新模拟会话的文本，或同一会话的后续文本；支持“说不清／暂时不知道”。空白输入直接返回校验错误。UI 明示“仅限虚构病例”。

**最小状态**：`session_id`、`turn_id`、`latest_user_message`、`collected_facts`、`missing_fields`、`asked_questions`、`followup_count`、`risk_flags`、`tool_results`、`next_action`、`final_result`、`trace`。会话状态和必要轨迹存 SQLite；本地开发数据不得提交。对每项未知信息保留“未问／已问未得／已知”区别，不把“说不清”当作肯定或否定答案。

**输出**：机器可校验的结果，至少包含 `status`、`known_facts`、`unknown_facts`、`tools_used`、`next_step`、`disclaimer`；追问时另有 `question`，风险分支另有规则编号与固定提示。`status` 可为 `followup`、`completed`、`risk_route`、`error`。已知事实须能追溯到用户文本，未知项明确列出；不输出确诊、概率化病名或具体药物方案。

## 3. 三个演示场景

| 场景 | 模拟输入与后续回答 | 预期路径 |
| --- | --- | --- |
| A 动态追问 | “头部不适”；后续“具体部位说不清”“挺明显的”“有点恶心，还觉得发热、胃不舒服” | 记录已问未得，不重复问部位；从其他维度追问；最多三次后停止普通追问，保留未知信息，经过风险检查再输出。 |
| B 信息足够 | “模拟人物头部不适两天，主要在前额，程度轻，暂无其他不适” | 跳过无价值追问；在非风险路径选择 `department_suggest` 或 `visit_preparation`，记录工具返回并生成摘要。 |
| C 预设风险 | “模拟人物突然呼吸困难” | 风险规则优先命中；停止普通追问和科室推荐，返回预设求助提示与规则编号。 |

场景描述只是测试输入和软件期望，不构成医疗判断。风险规则的内容和覆盖范围在 Day 9 由独立安全模块与固定测试确定。

## 4. 动作、工具与停止条件

一次决策只允许 `ASK_FOLLOWUP`、`CALL_TOOL`、`FINALIZE`。模型提出动作；Pydantic 校验动作和参数，工具注册表限制可调用名称。风险门控在动作选择前运行，最终输出前再次运行；命中预设风险时绕过普通模型决策。

| 工具 | 职责 | 出错退路 |
| --- | --- | --- |
| `risk_screen` | 独立规则检查并记录命中依据 | 不能判定时明确不确定，并提示寻求专业帮助 |
| `department_suggest` | 受限映射返回可咨询方向 | 无匹配返回“暂无法判断” |
| `visit_preparation` | 从已知事实生成可向专业人员描述的信息清单 | 返回不依赖虚构事实的通用清单 |

默认上限：普通追问 **3 次**，单次处理最多 **10 个图步骤**。问题已问未得也计入追问次数；拒绝相同语义的重复追问。信息足够、用户不再提供新信息、达到任一上限或命中风险分支时收束。工具超时、无效动作、输出校验失败时返回可读错误及轨迹，不编造成功结果。具体阈值可依据后续模拟评测调整，并同步更新测试。

## 5. 风险边界与非目标

- 仅用人工编造案例；界面、README 和最终输出明确标注演示用途。
- 风险分流是有限规则集，只展示软件怎样处理预设输入；不声称识别所有紧急情况。含糊表述保留不确定性，否定句和跨轮补充需要专门测试。
- 不收集真实患者信息，不公开部署给真实问诊使用；本地 `.env`、SQLite 会话库及轨迹中的用户文本不进入 Git。
- 当前 20 天主线不做疾病确诊、处方／剂量、临床效果评估、向量库、GraphRAG、微调或多 Agent 编排。

## 6. 验收标准

1. 三个演示场景均可从真实应用入口复现，轨迹显示每轮状态、动作、工具观察与停止原因。
2. 三次追问和十步上限有效；“说不清”不触发重复提问；空输入、未知工具、超时均有可读退路。
3. 风险门控先于普通动作；固定风险案例无漏分流，并检查否定句误分流。
4. 最终结果通过结构校验，已知与未知分开呈现，工具调用可追踪。
5. 后续评测集扩展至至少 30 个模拟案例，脚本真实运行并输出报告；指标仅描述这组案例上的软件行为。
