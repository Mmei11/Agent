# Agent 评测报告：Day 17 基线与 Day 18 修复复测

## 范围与口径

- 案例均为虚构输入，只检查软件控制流、状态和错误退路，不评价临床正确性。
- Agent 评测固定使用 mock 决策器，通过 FastAPI TestClient 调真实 API 和 graph；没有发起真实模型请求。
- E031 已把案例说明调整为 `department_suggest` 超时，与 runner 实际注入保持一致；runner 使用完整虚构 fixture 触发工具节点。
- `status=pass` 表示本报告里的软件断言通过，不等于模型答案质量通过。

| 问题 | 修复 | 复测结果 |

| 风险词覆盖不足 | 补充“胸口剧烈疼痛”“意识不清”“大量出血不止”等预设表达 | E018–E020 走 `intake → risk_check → output`，状态为 `risk_route` |

| 工具异常变成 HTTP 500 | tool 节点捕获异常，记录结构化错误；output 节点渲染 `error` 结果 | E031 返回 HTTP 200，`final_result.status=error` |

## 剩余限制

- 风险和含糊检查仍是关键词规则；本次覆盖的是固定评测集，不证明能识别所有表达。
- 拒答识别基于列举短语，未覆盖所有自然语言拒绝说法。
- 超时案例验证了 `department_suggest` 的异常退路；其他工具及不同异常类型仍需增加注入案例。
- Day 18 评测器未做真实模型重复采样，因此不报告模型答案稳定性或模型输出质量指标。
