# L1 药品信息边界（OTC 说明书查询）

> 这是产品规则，不是法律意见。上线前请让合规/律师确认。

## 定位

L1 只做“查说明书”，不做“推荐药”。它是药品信息查询，不是诊疗行为，也不是用药建议。

## 允许

- 用户主动说出一个具体药品名称；
- 只查 OTC 药品；
- 返回说明书摘要中的：适应症、禁忌、注意事项、不良反应、药物相互作用；
- 模型可以针对问题写 1–3 句开场白，并选择要展示的说明书段落，但只能复述给定字段；
- 明确标注来源、版本和是否已核实；
- 固定提示“不构成用药建议”“不能判断是否适合你”“请咨询药师或医生”。

## 禁止

- 根据症状推荐药品、排序或比较疗效；
- 给剂量、疗程、服用频次；
- 判断“你适合吃这个 / 你不能吃这个”；
- 处方药、特殊人群（儿童、孕妇、肝肾功能不全）的个体化判断；
- 未收录药品的补全、猜测或编造；
- 模型新增说明书以外的药品、剂量、诊断或治疗内容；
- 把说明书内容包装成“治疗建议”。

## 行为矩阵

| 用户输入 | 行为 |
|---|---|
| “布洛芬有什么禁忌” | 返回布洛芬说明书摘要 |
| “芬必得说明书” | 按别名匹配，返回布洛芬摘要 |
| “我头疼吃什么药” | 拒绝推荐，提示可查具体药品或咨询药师 |
| “阿莫西林能吃吗” | 处方药拒绝，交回医生/药师 |
| “某个没收录的药说明书” | 暂未收录，不编造 |
| “那需要注意什么” | 不是药品查询，交给正常追问回答 |

## 数据要求

- 生产环境只使用可追溯的官方说明书/NMPA 数据；
- 每条记录必须有：药品名、别名、适应症、禁忌、注意事项、不良反应、相互作用、来源、版本、`verified`；
- `verified=false` 的数据只能用于演示，必须在界面上标明“未核实”；
- 处方药不进入说明书库；
- 数据更新要版本化，旧版本可追溯；
- 建议由药师审核语料后再上线。

当前 `backend/app/drugs/labels.jsonl` 是项目内置示例数据（`verified=false`），**不能用于真实患者**。

## 接口与留痕

- 查询入口在问诊结果生成后的追问里；后续可以拆成独立的“药品说明书查询”页面；
- 说明书正文由受控数据拼接；模型只写开场白并选择段落，不生成说明书正文；
- 开场白要做剂量、推荐、个人适用性、其他药品名称校验，不通过就回退完整模板；
- trace 记录 `source=drug_label/drug_guard`、`drug_id`、`drug_verified`、
  `drug_answer_source=model/template`、`drug_intro_rejected`；
- 保留查询日志用于审计和不良事件反馈。
